# Reports – design

Owner request: a reporting tab where a person chooses what goes into the report (several choices),
adds filters (line, area, equipment ID, period), presses Build, and gets a professionally designed
report with charts that can be printed / saved as PDF and exported. Defaults below were chosen by the
design lead where the owner was silent.

## 1. Where it lives

- New page **Reports** (`/reports`), its own tab id `reports` in the access model (Hidden / View / Edit).
  View = build, preview, print, export, keep own saved templates. Edit = same (reserved for shared
  templates later). Seed levels: Admin Edit, Manager Edit, Engineer View, Viewer View.
- Own navigation section **Reports** (rail heading, single page, so no tab row). Phone: the More sheet
  lists it under the 'Reports' heading; it is not on the bottom bar.
- Backend: `reports` added to the tab list (schema tabAccessDefaults, role seeds, Access.js, TAB_IDS),
  per-user overrides work like other tabs. New client-writable preference key `saved_reports`
  (JSON, at most 20 templates, 20000 chars) next to `saved_views`.

## 2. Builder (left column on desktop, stacked on phone)

1. **Template** chips: 'Monthly management report', 'Area reliability review', 'Failure analysis',
   'Custom' and the person's saved templates (save as / rename / delete).
2. **Period**: presets (Last full month, This month so far, Last 3 months, Year to date, Custom range) and a
   'Compare with previous period' switch. Default Last full month in the data (latest complete month).
3. **Filters** (all optional, multi-select with search, chips show what is active): Line, Area, Equipment ID
   (equipment code, searchable by code or description), Classification, Criticality, Failures only.
   A one-line summary: 'N events, H area-hours in scope'.
4. **Sections** (checklist with group headings; every item has a one-line description; select all / none):
   - Summary: Cover page, Executive summary (headline KPIs with target status + takeaway sentences).
   - Performance: Daily stopped hours; Monthly stoppage by type; Downtime by classification;
     Downtime by area; Availability by area; MTBF and MTTR by area; Failure rate by area.
   - Causes: Top equipment by failure hours; Top reasons; Pareto by area / line / classification.
   - Reliability: Repeated failures (table + mini timelines); Longest events; MTBF vs MTTR quadrant;
     When failures start (hour x weekday).
   - Detail: Events table (top N by hours or all, N selectable), Data-quality appendix (records checked,
     kept as entered, left out), Methodology and definitions.
   Per-section options where meaningful (Top N 5/10/20, Hours/Count).
5. **Build report** (primary button, 44 px) -> preview. Build is a pure client calculation from the loaded
   events + master data, reusing the dashboard model/calc functions with the report's own filter state
   (it never changes the dashboards' shared filters). Missing data -> the section says so, never an empty box.

## 3. The report (preview = print = PDF)

- A4 portrait pages, consistent print stylesheet (`@page` margins, header/footer with report title,
  page numbers 'Page X of Y' via CSS counters where supported, plant name, generated date and user).
  Always the light, high-contrast report theme regardless of the app theme (so printed output is
  consistent); fonts from the app; charts use the same palettes/patterns (colour never the only cue).
- Cover: title, plant (Sokhna), period, comparison period, filter summary ('Line L.1 - Area CR, RM.1 -
  Equipment 131.ST200'), generated by / on, data coverage ('Data covers ... to ...'), small ACC mark.
- Table of contents with the chosen sections and page-start anchors.
- Each section: heading, one-sentence takeaway built only from real numbers, the chart(s) (SVG, crisp in print,
  no tooltips needed), a compact data table beneath when useful, a short note on how it is calculated.
- Executive summary: KPI strip (Total stoppage h, Failures, Availability B with target status, MTTR, MTBF where an
  area is selected), change vs previous period with arrow + words, 3-5 takeaway bullets.
- Data-quality appendix always states records excluded and kept-as-entered counts so numbers can be trusted.
- Never page-breaks inside a chart or a table row; large tables repeat their header row.
- Actions: Print / Save as PDF (window.print), Download Excel (one sheet per chosen section with the plotted
  data, plus a Summary sheet with the filters), Download CSV for table sections, Copy link to this report
  setup (query string restores template, period, filters, sections), Edit setup (back to builder).
  On the phone the preview scrolls vertically and scales pages to the screen width.

## 4. Other Phase 6 items (separate steps)

- Targets in Settings (availability %, MTBF h, MTTR h; blank = off) with red/green status on KPI cards, area
  charts and the report; month-vs-month comparison (Overview and Reliability: pick two months side by side);
  data-quality scorecard (flagged / kept / left out per month).
  **Built (dashboards):** the three targets are the settings `availability_target_pct` (also the threshold of the
  `availability_low` alert), `target_mtbf_h` and `target_mttr_h`; `src/dashboard/targets.ts` holds `getTargets(settings)` and the
  pure status logic (`targetStatus`, `kpiTargetStatuses`, `areaTargetStatuses`, `belowTargetCount`); availability and MTBF are
  on target at or above the target, MTTR at or below; a figure is judged as it is shown (0.1 points, 0.1 h, 0.01 h). The
  dashboard models expose it (`overviewModel().status / .belowTarget`, `areaReliabilityModel().status`), so the report's KPI strip
  can reuse the same values. Month vs month: `src/dashboard/monthCompare.ts` (`?mvm=YYYY-MM,YYYY-MM`). Scorecard:
  `src/validate/scorecard.ts` (`buildScorecard`).
- Event Explorer: Excel and CSV export of the filtered events; Saved views (filter sets) for dashboards via the
  `saved_views` preference.
  **Built (R2, exports and saved lists):**
  - `src/export/`: `xlsx.ts` (production .xlsx writer on fflate: shared strings, bold filled header, number formats 0.0 / 0.00 hours,
    0.0 % stored as a fraction, yyyy-mm-dd and yyyy-mm-dd hh:mm:ss as Excel serials, frozen header, autofilter over the data rows,
    widths capped at 60, valid unique sheet names), `csv.ts` (UTF-8 with BOM, comma, quotes doubled, CRLF; text that starts with
    `= + - @` gets a leading apostrophe), `table.ts` (one export table feeds both Excel and CSV), `reportExport.ts` (report model to
    sheets: the model's own tables cell for cell; plotted data where the chart shows more than the table, i.e. every day, the
    month-by-classification matrix, the hour-by-weekday grid, the three Pareto charts in one table), `eventsExport.ts`.
  - Report: 'Download Excel' (Summary sheet first, then one sheet per chosen section that has a table) and 'Download CSV' (a menu of those
    sections, one file per click, no total row, percentages as points under a "(%)" header) in the builder and the preview. File names:
    `ACC-downtime-<report-name>_<yyyy-mm or from_to_to>[_<section>].xlsx|csv`.
  - Saved templates (`saved_reports`): chips after the ready-made ones, Save as template / Rename / Delete (`src/reports/savedTemplates.ts`,
    `SavedTemplates.tsx`); a template keeps the period preset (Last full month stays relative), filters, sections, options. Names 1-60
    characters, unique ignoring case, not a ready-made template's name; at most 20.
  - Event Explorer 'Export' (Excel / CSV): exactly the filtered rows in list order, 23 columns, at most 50,000 rows (a note says when
    capped; the Excel file also has an 'Export info' sheet). It uses the events the page already loaded for the person.
  - Saved views (`saved_views`) for Overview, Pareto, Repeats, Reliability and Event Explorer: a 'Views' button by the filter bar
    (`src/views/`): apply, rename, delete, 'Save current filters as view'; at most 20 in all pages, query at most 1500 characters,
    names unique per page. A dashboard view is the filter query (the shared-filter store follows it); an Event Explorer view is its
    filter query (`q line area cls crit fail from to show sort`), applied by `/events?<query>`, which the page reads once and then
    removes from the address. The year switch is not part of a view.

## 5. Acceptance

- Selecting sections/filters and pressing Build produces exactly those sections, with numbers equal to the
  dashboards for the same filters (unit tests compare report models to dashboard models).
- Print preview (Playwright `page.pdf` + screenshots) shows cover, TOC, charts and tables without clipped content
  at A4; no sideways scroll at 360/390 in the builder; 44 px targets, 12 px min text on screen; no console errors;
  five app themes do not change the printed look.
- Access: Hidden removes the page; View can build; backend access tests and contract tests cover the new tab.
